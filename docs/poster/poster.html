Основные задачи

1. Разбор и категоризация операцийaccuracy 0,985, macro-F1 0,963 на 400 размеченных; без категории 0,06% оборота · categories.py, «Операции»
2. Регулярные платежи, счета, налоги из внешних источниковмеханизмы по истории, договоры и счета (ЭДО, 1С, OCR), налоговый календарь: режим по истории, ЕНП, УСН, НДС · mechanisms.py, tax_calendar.py
3. Прогноз остатка по дням на 30 днейансамбль X10, коридор P10–P90, производственный календарь РФ · POST /api/v1/forecasts
4. Риск разрыва: дата, сумма, вероятностьпервый день ниже порога, потребность в деньгах, вероятность с калибровкой X11, причины и действия · /explanation
5. Понятный интерфейс«30 июля не хватит 39 тыс. ₽: налоги и зарплата», график, колокольчик предупреждений, чат «Кассандра»

Задачи со звёздочкой

★1. Договоры, счета, налогипредоплата, отсрочка, график; задержка клиента по истории; ЕНП до 28-го, авансы УСН, НДС тремя долями — событие на дату
★2. План-факт и автообновлениепо дням и неделям, автосверка с выпиской, просроченный платёж — предупреждение, пересчёт и новая проверка риска
★3. Негативные сценарии «что если»клиент позже на 2–4 недели, выручка −10–30%, внеплановый расход, рост постоянных расходов; база и негатив на одном графике
★4. Интеграции и ручной вводбанк: кредиты, зарплатный проект, платёжки; 1С, ЭДО, ОФД, маркетплейс, ЕГРЮЛ/ЕГРИП, webhook HMAC; ввод фразой и OCR; источник события виден

Технические: минимальные

1. Прототип: история → прогноззагрузка CSV/ZIP/1С, Docker Compose, веб-клиент
2. Модуль категоризацииправила + ручная правка с датой знания
3. Модель с проверкой качествапротокол v3 без утечек; «Отладка»: любой датасет → журнал «Шаг 1…8», MAE, MSE, матрица ошибок, F1, Brier
4. График остатка и предупрежденияфакт, прогноз, P10–P90, точка разрыва; список предупреждений

Технические: дополнительные

1. Внешние системы и открытые данныеЕГРЮЛ/ЕГРИП через DaData, производственный календарь РФ, адаптеры банка, ОФД, маркетплейса
2. Обновление без полного пересчётановое событие — 10–15 мс без модели; новая выписка — только затронутый счёт
3. Граничные случаи и пропускинесверки не «чинятся», дубли, закрытые счета, история < 7 дней — отказ, < 90 — низкое доверие
4–5. Сравнение подходов · схема архитектуры11 вариантов на одинаковых окнах (docs/ml_results.md); схема — README
6–7. Тесты · безопасность317 pytest + 51 Flutter; Bearer-токены, права на счёт, без назначений, ИНН и ключей в логах

Архитектура

Слои с чёткими границами

Flutter web «Kassandra» — прогноз, разрыв, что если, календарь, операции, план-факт, источники, отладка, чат
Dash — технический режим
Внешние системы — 1С, банк, ЭДО, ОФД, маркетплейс, webhook, DaData
FastAPI /api/v1 — Bearer-токены, права на счёт, ответы по Pydantic-контрактам (docs/openapi.json)
Сервисы — оркестрация, версии данных и событий с датой знания, план-факт, предупреждения, пересчёт без модели
ИИ-надстройка — LLM проверяет прогноз, OCR, чат через MCP-инструменты; цифры считает сервис
cashflow_ml — признаки, HGB, ансамбль, банк ошибок, калибровка
cashflow_domain — траектория, риск, сценарии, деньги в копейках
SQLite — операции, события, прогнозы, ревизии
Запуск: docker compose up --build · make check
