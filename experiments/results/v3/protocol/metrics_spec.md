# Спецификация метрик протокола v3 (X0; docs/ml_protocol.md D1, D2, D3)

Код: `src/cashflow_ml/protocol_v3.py`. Конфигурация: `experiments/p3.json`. Команда: `cashflow evaluate-v3`.

## Срезы

| Набор | Срезы as_of | Назначение |
|---|---|---|
| Обучение | модель v2 `trained_to = 2025-12-31` (цели обучения не позже этой даты) | как в v2 |
| Калибровка | 2026-01-01, 01-08, 01-15, 01-22, 01-29 | цели до 2026-02-28; не заходят в выбор (проверяет `expand_origins`) |
| Выбор | недельные 2026-03-01 ... 2026-05-31 (14 срезов, цели до 2026-06-30) | решение по правилу D1 |
| Ретро | недельные 2026-07-01 ... 2026-08-26 (9 срезов, цели до 2026-09-25) | только отчёт; уже просматривалась в v2 |

Пригодность окна: `evaluation.eligible` — дни as_of-89 ... as_of+30 имеют `valid`. Окна и маски одинаковы для всех методов: если любой метод падает на окне, окно выбывает для всех и попадает в `dropped_windows.json`.
Методу передаются операции с `operation_date <= as_of` (категории с учётом ревизий `known_at <= as_of`) и дневные строки не позже as_of.

## Цель D3 (основная)

`target[h] = EOD[as_of+h] - сумма поступлений финансирования за (as_of, as_of+h]`, h = 1..30. Финансирование: `is_financing(category, 'in')` из X1 (owner_funding, loan_in, own_transfer на вход), итоговая категория архива. Все методы прогнозируют остаток от наблюдаемого `EOD[as_of]` без нового внешнего финансирования, включая constant. Вторичная цель — наблюдаемый EOD (`observed`, `obs_*` в `windows.csv`).

## Метка D2

Пороговое значение T = `threshold_minor` (по умолчанию 0). День d «стрессовый», если он валиден и: `EOD[d] < T` (а) либо `F[d] > 0` и `EOD[d] - F[d] < T` (б), где F[d] — финансирование дня. Эпизод — максимальная серия подряд идущих стрессовых дней (невалидный день разрывает серию). Событие — первый день эпизода, при условии что предыдущий день валиден и не стрессовый (поэтому дефицит, существовавший с первого дня данных или после пропуска покрытия, новым не считается). Тип события: `negative_eod`, если EOD первого дня < T, иначе `financing`. Дефицит эпизода = max(T - (EOD - F)) по его дням. Текущий дефицит на as_of (`EOD[as_of] < T`) — отдельный признак окна `current_deficit`: такие окна исключены из тревог, ложных тревог, recall и Brier и считаются отдельно (`windows_current_deficit`).
Манифест событий: `event_manifest.json` и `events.csv` — части: до 2025-12-31, январь-февраль 2026, март-июнь, июль-сентябрь; число событий и компаний, отдельно отрицательный EOD и пополнение.

## Метрики прогноза (D1)

Ошибки считаются по цели D3, в копейках внутри, в рублях в отчёте.
- `MAE траектории` окна = среднее |target - прогноз| по 30 дням. `MAE дня 30` = |target[30] - прогноз[30]|. `MAE минимума` = |min(target) - min(прогноз)|.
- Skill компании = `1 - сумма ошибки метода по окнам компании / сумма ошибки constant по тем же окнам` (по траектории и по минимуму). Компании с нулевой суммой ошибки constant пропускаются. В отчёт идёт медиана по компаниям и 95% интервал бутстрэпа по компаниям (1000 повторов, seed 42, перцентили 2,5 и 97,5), доля компаний со skill > 0.
- Нормированная ошибка = MAE траектории / средний дневной оборот (поступления + списания) за последние 90 дней до as_of, не менее 1 рубля; в отчёте макро по компаниям. Макро-MAE в рублях: среднее по компаниям средних MAE окон.

## Риск (D1, метка D2)

Тревога точечного метода: срез без текущего дефицита, где прогнозируемая траектория имеет остаток < T хотя бы в одном из 30 дней. Для вероятностных методов порог вероятности задаётся отдельно (X6); раннер хранит `p_gap_30d`.
- Recall@7d: событие учитывается, если есть срез без текущего дефицита, где оно наступает через 7-30 дней (`scorable`). Событие найдено, если на хотя бы одном таком срезе есть тревога. Одно событие (счёт, дата) даёт максимум один TP. Интервал Уилсона 95%.
- Ложная тревога: срез без текущего дефицита с тревогой, где в ближайших 30 днях нет ни одного события D2. Тревога, на которой событие наступает через 1-6 дней, не ложная и не засчитывается в recall@7d. Ложные тревоги на счёт-месяц = число таких срезов / (срезов без текущего дефицита x шаг в днях / 30,4375). Бюджет — 1.
- Ошибка даты: срезы с тревогой и событием в 30 днях; |день первого пересечения порога в прогнозе - день первого события|. Доля с ошибкой <= 3 дней (`date_within_tolerance`), медиана. Это оконная статистика, срезы одного события зависимы.
- Ошибка суммы дефицита: на тех же срезах |max(0, T - min(прогноз)) - max(0, T - min(target))| в рублях (среднее и медиана).

## Вероятность

Для методов с `p_gap_30d`: метка = есть событие D2 в 30 днях (срезы без текущего дефицита). Brier; опорная частота — доля меток среди калибровочных срезов (честная) и среди самого набора (оптимистичная); `brier_skill = 1 - Brier / Brier_базы`. Надёжность — 10 равных бинов: n, средняя вероятность, наблюдаемая частота.

## Правило выбора (`d1_decision`)

Кандидат проходит, если на выборе: медиана skill минимума > 0; медиана skill траектории >= -0,02; ложных тревог на счёт-месяц <= бюджета; recall@7d не хуже default. Constant не может быть default.

## Ограничения

- Окна внутри компании зависимы (срезы перекрываются), бутстрэп по компаниям их не разделяет.
- Событий мало: см. `events_scorable` в отчёте; recall — грубая оценка.
