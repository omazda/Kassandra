> **Коррекция после аудита (финальная интеграция).** Таблицы выше пересчитаны с исправленной событийной метрикой: событие найдено, только если дата тревоги в пределах ±3 дней от даты события; тревога на другую дату — ложная. Текстовые комментарии ниже написаны до исправления: заявленные в них recall (в частности 0,899, 0,797, 0,884) и «ложных тревог 0,394» **устарели** (для S3 теперь 0,290 = 20/69 и 0,654). Решение «default = structural (S3)» **отменено**: варианты с ретро-реестром (S2, S3) знают будущие оплаты и не могут быть основанием для default (в продукте на правом краю данных реестр отключён). Честные варианты, прошедшие D1 против weekday: hgb_v2, hgb_full, hgb_mech, shape_only. Default продукта: hgb (hgb_v2: skill траектории -0,003, минимума +0,157, recall 17/69, ложных 0,187). См. `experiments/results/v3/audit/` и docs/ml_results.md.

## Комментарий и ограничения

1. **Решение D1.** Структурная модель S3 (механизмы X2 + налоговый календарь X7 + реестр документов X3 + остаток по дням недели) проходит все четыре проверки правила против текущего default (weekday) на срезе выбора: skill минимума +0,363 (>0), skill траектории +0,004 (>= -0,02), ложных тревог 0,394 на счёт-месяц (бюджет 1), recall@7d 0,899 (62 из 69 событий) против 0,551 (38 из 69) у weekday. S3 становится default в API и UI. Из методов продукта по skill минимума и recall S3 лучше всех (HGB D: +0,225 и 0,725; hgb_v2: +0,157 и 0,580). shape_only (ориентир, не продуктовый метод) проходит правило тоже, но уступает S3 по минимуму и recall.
2. **Цели плана (раздел 5).** Skill минимума >= +0,35: достигнут на выборе (+0,363, интервал 0,309..0,408) и на ретро (+0,356). Skill траектории >= +0,05: не достигнут (+0,004 на выборе, +0,006 на ретро, интервалы включают нуль). Recall@7d >= 0,6 при <= 1 ложной тревоге: достигнут (0,899 и 0,837). Ошибка траектории фактически на уровне constant: модель лучше видит провал (минимум), но не уменьшает среднюю ошибку остатка.
3. **E03 (матрица 2x2).** Простая модель: механизмы дают skill минимума +0,083 [+0,045; +0,122] (B - A) на выборе и +0,084 [+0,052; +0,138] на ретро; skill траектории +0,036 [+0,000; +0,078] и +0,021 [-0,025; +0,044]. HGB: механизмы (D - C) на выборе не меняют ни минимум (+0,004 [-0,036; +0,052]), ни траекторию (-0,001 [-0,060; +0,051]); recall 39 -> 50 событий из 69, но ложных тревог 0,125 -> 0,257. На ретро D - C: траектория +0,105 [+0,048; +0,151], минимум -0,044 [-0,099; +0,004]. Знак эффекта механизмов для HGB нестабилен между выбором и ретро.
4. **E09 (польза источников).** S1 (без реестра и налогов) -> S2 (+ реестр) -> S3 (+ налоги), выбор: skill минимума +0,186 -> +0,328 -> +0,363; recall@7d 0,797 -> 0,884 -> 0,899. Парная разность реестра (S2 - S1) на выборе: минимум +0,061 [+0,021; +0,118], траектория +0,014 [+0,000; +0,048]; на ретро: минимум +0,004 [+0,000; +0,047], траектория +0,003 [-0,001; +0,014], то есть на ретро польза реестра отдельно не отделима от нуля. Реестр + налоги вместе (S3 - S1): выбор +0,096 [+0,031; +0,155] по минимуму, ретро +0,021 [+0,006; +0,068]. Налоги отдельно: разность по минимуму 0,000 в обоих срезах (+0,000 [-0,001; +0,000] к реестру на выборе), по траектории -0,000..+0,001; налоговый календарь меняет сумму ЕНП в месяцы начисления, но на минимум остатка по 30-дневным окнам влияет слабо. Эффект налогового календаря на ЕНП измерен отдельно в отчёте X7.
5. **Реестр оптимистичен (D6).** Реестр содержит только документы, которые были оплачены к концу архива, и знает, что оплата будет. Выживаемость завышает полезность реестра на неизвестную величину; чувствительность «клиент не заплатит» не оценивалась (сценарий X9 есть, измерения нет). В продукте при as_of на конец архива (без оплат после as_of) реестр отключается автоматически, документы остаются в остатке; пользовательский реестр (CSV, события) подтверждает и замещает предположения как раньше.
6. **Alpha = 0.** Затухающий тренд на калибровке (557 окон, 116 компаний, 5 январских срезов) только ухудшал нормированную MAE (3,243 при 0; 3,285 при 0,25; 3,471 при 1,0). Выбран alpha = 0, поэтому тренд в итоговой модели выключен, S1 совпадает с B. Реализация тренда оставлена (apply_trend, alpha в alpha.json), но она не вносит вклада в метрики. Определение тренда (разность среднего чистого остатка за 28 и 90 дней, затухание 0,9^h) выбрано мной до просмотра результатов, другие формы не пробовались.
7. **Неопределённость выбора.** Событий на выборе 69, на ретро 49; окна одной компании перекрываются на 23 дня, бутстрэп по компаниям эту зависимость не учитывает, интервалы оптимистичны. Ложные тревоги S3 (0,394) выше, чем у weekday (0,152): за recall платим тревогами.
8. **Что не сравнивалось на равных.** hgb_v2 обучен на потоке с финансированием, поэтому в 2x2 вместо него контрольная C: тот же HGB, обученный на потоках D3 без финансирования (config p1.json, seed 42, trained_to 2025-12-31, 1454 окна). D - C различаются только вычитанием операций механизмов.
9. **Подбор.** Единственный подбираемый параметр (alpha) выбран на калибровке. Срезы выбора и ретро для подбора не использовались. Состав методов и правило отбора кандидата заданы до запуска.
