# X8: короткая история и новые компании (E07)

Метод: `src/cashflow_ml/cold_start.py`, маршрутизация в `structural.structural_forecast`.
Запуск: `uv run python experiments/results/v3/x8/evaluate_x8.py` (около 7 минут, 2 процесса).
Все метрики по цели D3 (остаток без нового финансирования), горизонт 30 дней, протокол X0
(skill к constant, медиана по компаниям, бутстрэп 1000, seed 42). Окна одной компании
перекрываются, интервалы оптимистичны.

## Что сделано

* История < 7 дней: отказ (`ColdStartRefusal`) с объяснением, в `confidence` уровень `none`.
* 7-29 дней: отраслевой prior, предупреждение «очень низкое доверие», интервал P10-P90 расширен
  в 1,5 раза. 30-89 дней: тот же prior, доверие «низкое», интервал.
* 90-364 дня: обычная структурная модель, доверие «среднее»; от 365: «высокое».
* Prior: медиана по донорам (другие компании той же отрасли с историей >= 90 дней на as_of, при
  меньше 3 донорах отрасли - все компании) профиля «поток на рабочий день / оборот» по потоку,
  дню недели и трети месяца за последние 180 дней донора, только операции <= as_of. Оборот
  компании берётся по её собственной истории. Собственный профиль по дням недели входит с весом
  `min(1, n / full_at)`. События механизмов, налогов и реестра в режиме prior не строятся (поток
  prior уже включает всё, двойной счёт исключён).
* Параметры по калибровочным срезам (январь 2026, история обрезана до 14/30/60 дней, 1561 окно):
  `full_at=720`, `shrink=0,25` (сжатие потока к нулю, как у constant), `k=0,5` (множитель
  интервала; покрытие 80% целится на pointwise P10-P90). Файл `params.json`, сетка в нём же.

## Ограничения и честность

* Параметры подбирались на калибровке, но порядок был такой: сначала сетка `full_at` {45,90,180},
  `k` {0,75..2}: оба параметра упёрлись в край; сетка расширена (калибровка), затем прогон на
  срезах выбора показал, что prior хуже structural по нормированной MAE на 14 и 28 днях;
  после этого я добавил параметр `shrink` и пересчитал калибровку заново. То есть решение
  добавить shrink принято после просмотра выбора; сами значения параметров - только по
  калибровке. Цифры выбора слегка оптимистичны для prior. `shrink` упёрся в край сетки (0,25).
* Реальных новых компаний 32, из них окна <90 дней дают только 49 (7-29) и 119 (30-89) окон; выводы
  по естественным группам слабые, интервалы широкие.
* Prior не использует реестр документов, налоговый календарь и механизмы. В реальном продукте
  новая компания с загруженной выпиской за неделю не имеет документов с датами оплат, поэтому это
  осознанно.
* Доноры строятся по данным архива на as_of; на 150 компаниях в отрасли 7-14 доноров, при < 3 -
  все компании. В продукте с одной компанией prior пустой: тогда режим `own_only` с предупреждением.
* Обрезка истории в опыте A имитирует новую компанию (остальной архив остаётся у доноров); баланс
  на as_of известен.
